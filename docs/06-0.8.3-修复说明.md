# 0.8.3 修复说明：荣耀 / 旧版 Android WebView 上「点搜索结果没反应」

## 现象

同一套玄览，小米手机正常，荣耀手机可以打开页面、可以搜索，但点击搜索结果里的文件或
文件夹没有任何反应；换一台手机（小米）打开同样的文件却正常。

## 复现环境

从飞牛网关的访问日志（`/usr/trim/nginx/logs/access.log`）可以区分两台设备：

| 设备 | User-Agent 关键信息 | 结果 |
| --- | --- | --- |
| 小米 | `Android 14 … Chrome/120.0.6099.193`，飞牛 App 内置 WebView | 图片、PDF 均正常 |
| 荣耀 | `Android 10; CHL-AL00 … Chrome/83.0.4103.106`，飞牛 App 内置 WebView | 点文件、文件夹均无可见反应 |

荣耀手机访问时，服务端实际收到了这些请求，且全部 `200`：

- `GET /app/xuanlan/api/search?q=…` —— 搜索正常
- `GET /app/xuanlan/api/dir?path=…` ×7 —— 点击文件夹确实触发了定位面板
- `GET /app/xuanlan/api/file?path=…epub` ×2 —— 点击文件确实触发了打开请求

**结论：点击事件和接口都正常，问题只在前端渲染层——浮层被创建了，但用户看不见。**

## 根因

0.8.2 的浮层使用 CSS `inset` 简写定位：

```css
.openwin { position: fixed; inset: 26px; }
.finder, .setmask, .modal { position: fixed; inset: 0; }
```

`inset` 是 `top/right/bottom/left` 的简写，**Chrome 87 才支持**。荣耀手机的内置 WebView
是 Chrome 83（Android 10 系统自带，飞牛 App 直接复用系统 WebView），会忽略该声明。
于是这些固定定位元素退回「没有偏移量、宽度按内容收缩、高度按内容计算」的状态：

- 结果列表较短时，子窗口会缩成两三百像素的小盒子，落在页面底部；
- 结果列表很长时，它按静态位置排到列表后面，完全落在屏幕外；
- 定位、设置、回收站等全屏遮罩同样失效。

从界面上看，就是「点了没反应」。JS 里 `openwin.style.inset = '10px'` 也用了同一个简写，
动态最大化时同样失效。

另外，移动端高度用了 `100dvh`（Chrome 108+），在 Chrome 83 上会整条声明失效，需要 `vh` 回退。

## 修复内容

### 1. 浮层定位改为长写（核心）

`ui/index.html`：

- `.openwin`、`.finder`、`.setmask`、`.modal` 的 `inset` 全部改为
  `top/right/bottom/left` 长写；
- JS 新增 `setOwBox()`，`applyOw()` 不再写 `style.inset`，改为分别写四个方向；
- 手机/窄屏（`pointer:coarse` 或宽度 ≤ 620px）打开子窗口贴边全屏，桌面保留 10px 边距。

### 2. 视口单位回退

- `.ctx.sheet` 的 `max-height:72dvh` 前补 `72vh`；
- 移动端设置/定位/回收站面板的 `max-height:calc(100dvh …)` 前补 `100vh` 版本；
- `.finder .panel` 的 `height` 同样补 `vh` 回退。

现代浏览器会继续使用后一条 `dvh` 声明，旧 WebView 使用 `vh`，两边都不丢样式。

### 3. 无内置阅读器的格式不再「空白面板」

`EPUB/XPS/OXPS/DjVu/FB2` 归在 PDF 分类下，但只有 `.pdf` 有内置阅读器。旧逻辑会把它们
直接塞进 iframe，服务端按 `application/octet-stream` 返回，浏览器只会静默下载或显示空白。
现在改为：

- 已安装「在线预览」→ 转交 `/app/trim-preview/`；
- 已安装「文档服务」→ 转交文档服务；
- 否则明确弹窗询问是否下载到本地。

### 4. PDF 失败提示

内置阅读器使用 pdf.js 4.10，官方要求 Chrome 98+。在 Chrome 83 上模块解析会失败。
现在会显示具体原因，并提示更新系统 WebView，或用「在新标签打开」下载后查看，不再只报一行
原始异常。

## 验证

- **UI 行为**：用 headless Chromium 加载真实 `ui/index.html`、模拟 API，在 390×844 视口下
  依次触发「打开文件 / 打开 EPUB / 定位文件夹 / 设置 / 回收站」：
  - 子窗口：`0,0,390×844`，iframe 指向 `/api/file?path=…`；
  - 定位、设置、回收站：均 `0,0,390×844`；
  - EPUB：弹出下载确认，iframe 不再被指向 octet-stream。
- **桌面回归**：1280×800 下子窗口为 `10,10,1260×780`，浮层正常。
- **旧内核模拟**：把定位声明去掉模拟 Chrome 83，复现出旧版子窗口只有 `300×196`、
  `y=651`；补上长写后恢复全屏，与根因判断一致。
- **服务端**：`bin/markdown_test`、`tests/smoke.sh` 通过；0.8.3 打包产物中的
  `ui/index.html` 与仓库源码 md5 一致。

> 说明：本轮没有在真实荣耀手机上做像素级截图验证，设备信息来自网关访问日志的 UA；
> 旧内核行为按 CSS 规范与去掉声明的模拟结果推断。实际设备复测请以安装 0.8.3 后的
> 表现为准。

## 升级

- 安装包：`dist/xuanlan_0.8.3_amd64.fpk`（应用中心手动安装/更新）；
- 索引仍是 v2，从 0.8.1/0.8.2 升级不触发全量重建；
- 升级会同时更新二进制与前端。若只替换前端，0.8.1 后端没有 `/api/markdown`，
  `.md` 预览会失败，因此建议整包升级。

## 仍受限制的场景

1. **EPUB**：0.8.3 只能下载或交给在线预览应用；0.8.4 已增加内置阅读器，见
   [EPUB 预览说明](07-EPUB-预览说明.md)。XPS/DjVu/FB2 仍没有对应阅读器；
2. **PDF（Chrome 83 等旧 WebView）**：pdf.js 4.10 无法运行。可选方案：
   - 更新系统 WebView / 用系统浏览器打开玄览；
   - 若安装了第三方的「PDF 阅读器」（如 `leelaa.pdfload`），可增加「用 PDF 阅读器打开」回落；
   - 服务端 PDF 转图片（需引入 Ghostscript 等外部程序，安全与维护成本较高，暂未采用）。
3. 旧 WebView 不支持 flex `gap`（Chrome 84+），按钮间距会偏紧，但不影响功能。

## 回滚

重新安装上一版 FPK（`dist/xuanlan_0.8.2_amd64.fpk`）即可；索引格式未变，无需迁移数据。
