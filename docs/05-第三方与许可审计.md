# 第三方代码与许可审计（2026-11-02）

## 审计方法

1. `find src -name '*.c' -o -name '*.h' | xargs wc -l` 统计自研代码规模；
2. `ldd bin/xuanlan` 确认动态链接对象；
3. `grep '#include <'` 列出全部系统头文件依赖，确认没有第三方 C 库；
4. 全仓检索 `*.cpp/*.hpp`、`GPL`、`pdfjs`、`feather` 关键词；
5. 检查分发包 `dist/*.fpk` 内是否携带许可证文本。

## 没有踩的坑

- 没有把 kerything（GPL-3.0）代码“改一改”搬进来。评估阶段只读过它的架构说明，最终用 C11 重写；
  仓库里不存在 C++ 源文件，`grep -r 'GPL' src/` 为空。
- 没有链接 `libext2fs`。ext4 读取器按公开磁盘格式规范手写：superblock、组描述符、inode 位图、
  extent 树、`ext4_dir_entry_2`。
- 没有反编译飞牛二进制。`trimacl` 的 xattr 结构是通过样本对比 + CLI 差分测试得出的黑盒结论；
  `X-Trim-Userid` 是通过打印请求头发现的。
- 前端没有用 React/Vue 等框架，pdf.js 是唯一的 JS 依赖。

## 仍需注意的边界

1. **商标**：包里不能出现“飞牛”“fnOS”“OnlyOffice”作为产品名或图标；界面文案目前只用于
   “打开方式”的功能描述（“飞牛文档（OnlyOffice）”指代系统中的既有应用），属于指示性使用。
   若上架应用中心，建议改为“文档服务”“在线预览”等中性表述。
2. **反向工程的合同风险**：技术层面不构成复制，但飞牛的用户协议若禁止反向工程，
   分发时可能触及合同条款而非著作权。自用不受影响，公开分发需自行评估。
3. **深链与私有接口**：`/appview`、`/docs/preview`、`X-Trim-*` 都是未公开接口，
   版本升级可能失效；不属于版权问题，属于兼容性风险。
4. **图标相似度**：应用图标为脚本生成的放大镜 + 索引线，与飞牛自有图标无重合。

## 结论

当前程序由本项目代码构成，第三方只有 pdf.js（Apache-2.0）与一个 Feather 图标路径（MIT），
均已随包附带许可证文本；没有任何 GPL 代码进入二进制，也没有复制飞牛或 Everything 的实现。
