# 09 · 团队文件夹权限作用域与扫描白名单

> 状态：设计稿 v1；P0–P9 已落地（2026-11-18，0.9.0 公测），P10 可选未做。
> 实现状态以 §17 为准；§8 的索引 v3/视图是未来设计。
> 适用：玄览 0.8.x（C 服务 + 每卷单文件快照）
> 关联：[perm.c](../src/perm.c)（TrimACL 求值）、[scan.c](../src/scan.c)（目录遍历）、
> [httpd.c](../src/httpd.c)（身份与检索范围）、[snapshot.c](../src/snapshot.c)（快照格式）、
> [04-P2增量与ACL.md](04-P2增量与ACL.md)（ACL 实测结论）

## 0. 结论摘要

1. **现状**：默认配置下 `/volN/@team/**` 被当作 `@` 开头的隐藏项整棵跳过，团队文件不进索引
   （关闭“忽略隐藏项”会连 `@appdata` 一起纳入，且不按人裁剪）；
   `scope-<uid>.txt` 只是查询期按路径前缀过滤，不改变扫描，也不改变索引内容。
2. **方案**：把现有「检索范围」升级为**扫描作用域（ScanScope）**，并让扫描器按作用域工作：

   ```text
   请求身份 / 账号表 / 配置
            │
            ▼
   主体 principal ──► 作用域解析 ScopeResolver ──► ScanScope(uid)
                                                        │
   卷与远程挂载 ──► 共享扫描（@team + ACL）──► idx/volN.idx
                └─ 单元独立扫描 ─────────────► idx/units/<unit>/volN.idx
                                                        │
   查询 ──► QueryRouter（shared / u<uid> / g<gid>）
         ──► shared 走查询期 ACL；单元走独立快照 + delta
   ```

3. **两级跳过**：
   - **L1 物理跳过**：一棵子树若对**所有可索引主体**都不可穿越，扫描器连 `open()` 都不做；
   - **L2 用户跳过**：某用户无权限的目录不进入该用户的视图，其记录不参与该用户的任何查询；
   - **隔离/混合模式（可选）**：管理员在后台选 `shared` / `isolated` / `hybrid`；
     `isolated` 按用户物理建索引；`hybrid` 默认共享、按组隔离、未分类组回退共享（详见 §15）。
4. **权限标识来源**：请求身份用飞牛网关注入头；目录权限以 `system.trim_acl` xattr 为权威；
   用户/组来自 `passwd`/`group`；`scope.json` 只做覆盖、远程存储与测试；飞牛 API 仅用于
   账号/团队枚举与校验，**不进扫描热路径**。
5. **远程挂载**：新增 `storage provider` 抽象（local / smb / nfs / webdav / s3 / usb），
   扫描、ACL、健康检查、挂载生命周期都走同一接口，后续接入新存储只加一个 provider。

## 1. 现状与缺口

| # | 事实（代码位置） | 后果 |
|---|---|---|
| 1 | `scan_name_skip()` 对 `.`、`@` 开头一律跳过（[scan.c](../src/scan.c)） | 默认配置下 `/volN/@team/**` 整棵子树不入索引；团队文件搜不到 |
| 2 | `handle_acl_list()` 跳过 `.`/`@` 开头的顶层目录（[httpd.c](../src/httpd.c)） | 团队目录不会出现在「检索范围」候选里 |
| 3 | `scope_default()` 只收 `kind=granted` 与纯数字家目录 | 即使团队目录可列，也不会进默认范围 |
| 4 | `scope_allows()` 只在搜索结果输出时按前缀过滤 | 只省展示、不省扫描；索引仍保存越权路径 |
| 5 | `handle_search()` 对每条候选做 `stat` + `perm_dir_listable()`（读 xattr） | 深目录/冷缓存有开销，且易受 TOCTOU 影响 |
| 6 | `build_one()` 每卷一个快照，root 全量扫 | 无「按人分配扫描范围」的概念 |
| 7 | ext4 裸设备读（`fsreader_ext4_scan()`）绕过 `scan.c` | 权限跳过逻辑无法直接复用 |
| 8 | fanotify 只处理 CREATE/MOVED/DELETE（`live.c`） | 改 ACL（setxattr）不会触发增量刷新 |

因此当前并不存在「团队文件夹 + 按人授权 + 扫描期跳过」的能力；本方案要把这三件事一次补齐，
同时保持单卷快照、毫秒查询和现有 ACL 语义不变。

### 1.1 目标

- 团队文件夹（`/volN/@team/<team>`，或配置指定的普通目录）成为**一等扫描根**；
- 每个用户的可扫描目录范围由 ACL 推导，**无权限的子树不进入该用户的结果**；
- 扫描期能剪枝：无人可访问的子树不打开，减少 IO 与索引体积；
- 查询不再逐条读 xattr，权限过滤退化为位图判断；
- 预留远程挂载 provider，后续接入 SMB/NFS/WebDAV/对象存储不改扫描器；
- 权限来源、缓存失效、失败回退都有明确规则，默认 fail-closed。

### 1.2 非目标

- 不做写权限改造（复制/移动/删除继续走现有 `perm_*` 复核）；
- 不做内容全文检索；
- 不在本期实现远程存储的实时事件（CIFS/NFS 用周期对账）；
- 不改变飞牛网关的身份注入机制。

### 1.3 一个必须先定下的取舍

| 模式 | 索引单元 | 索引体积 | 「无权限不扫描」 | 适用 |
|---|---|---|---|---|
| **shared（系统默认）** | 每卷 1 份 | 1 份 + 每卷每用户视图 | L1 物理跳过 + L2 视图跳过 | 只要求“搜不到/打不开” |
| **isolated** | 每用户 1 份 | N 份 | 对该用户物理跳过 | 全员强隔离、用户少、合规 |
| **hybrid（推荐生产）** | 共享 1 份 + 每个隔离组 1 份 | 1 + K 份 | 隔离组物理跳过；共享用户 L1/L2 | 默认共享 + 敏感组隔离 |

结论：

- `scanMode` 的**系统默认值仍是 `shared`**，保持升级后的行为不变；
- **生产建议直接选 `hybrid`，且 `isolatedGroups` 先留空**：此时行为等价 `shared`，
  后续把财务/研发/外包组加入 isolated 分类即可，无需切换全局模式、无需重建全部用户；
- 只有“所有用户都必须物理隔离”时才选 `isolated`；
- “每个人能搜到的范围”三种模式都由同一套 `ScanScope` 推导，差别只在**物理扫描单元**和
  **查询入口**，权限语义不变。

hybrid 的组分类、回退规则、配置默认值与存储方案见 §15。

## 2. 术语与不变量

- **主体 principal**：`{ uid, gids[], is_admin }`，权限判定的对象，不是进程身份。
- **可穿越 traverse**：路径上每一级都有 `x`；没有 `x` 连子目录都到不了。
- **可列 read**：目标目录自身有 `r`（且祖先可穿越）。
- **作用域 ScanScope**：某 uid 的允许/排除目录集合。**只能收窄 ACL，不能放大**。
- **目录掩码 dir mask**：一个目录对全部主体的 `read` / `traverse` 位图。
- **视图 view**：把目录掩码投影成「该用户可见的 scope_id 集合」，查询时 O(1) 判断。

不变量：

1. **ACL 是上限**：手工配置、团队名单、远程 provider 都不能让用户看到 ACL 拒绝的路径
   （显式 `adminOverride` 除外，需审计）。
2. **默认拒绝**：身份缺失、ACL 损坏、provider 离线、视图过期且无法复核时，一律不可见。
3. **服务端复核**：索引/视图只用于「找得到」，打开/下载/预览/文件操作仍按实时 ACL 复核。

## 3. 总体架构

```text
                        ┌──────────────────────────────┐
  飞牛网关              │ 身份解析（仅 unix socket 可信）│
  X-Trim-Userid  ──────►│ uid / is_admin / username     │
  X-Trim-Isadmin        └──────────────┬───────────────┘
                                        │
  passwd / group ───────────────┐       ▼
  scope.json / scanmode.json ───┼──► ScopeResolver ──► ScanScope(uid)
  system.trim_acl xattr ────────┘       │                 │
                                        │                 │
  卷 / 远程 mount ──► 共享扫描（@team + ACL）──► idx/volN.idx
                    └─ 单元独立扫描 ──────────► idx/units/<unit>/volN.idx
                                        │
                                        ▼
                              QueryRouter（shared / u<uid> / g<gid>）
                                        │
                    ┌───────────────────┴───────────────────┐
                    ▼                                       ▼
          shared：查询期 ACL 复核                 单元：独立快照 + delta
                    │                                       │
                    └───────────────┬───────────────────────┘
                                    ▼
                      打开/下载/预览：实时 perm_* 复核（fail-closed）
```

> 图中“共享扫描 / 单元独立扫描 / QueryRouter”是**当前实现**；
> 索引 v3 的掩码/视图是 §8 的未来设计，尚未接入。

## 4. 权限标识来源

### 4.1 请求身份（谁在查）

| 来源 | 头/方式 | 可信条件 | 用途 | 失败处理 |
|---|---|---|---|---|
| 飞牛网关 | `X-Trim-Userid`、`X-Trim-Username`、`X-Trim-Isadmin` | 仅 unix socket 对端为 root/服务 uid/www-data | 请求 uid、管理员标记 | 回落下一条 |
| 网关兼容头 | `x-nas-uid` | 同上，仅 unix socket | 旧版网关 | 回落下一条 |
| 会话 Cookie | `Cookie` → `trim_http_cgi` | TCP 请求唯一合法路径 | 取 uid | 401 |
| 启动兜底 | `XL_ACL_UID` | 仅调试/单管理员 | 固定 uid | 无身份则 401 |

**TCP 上的 `X-Trim-*` 一律忽略**（现有 `handle_client()` 已如此），扫描器不读请求头，
只读「主体表」，两者不要混用。

### 4.2 目录权限（能看什么）——权威来源

`system.trim_acl` xattr，格式与 [04-P2增量与ACL.md](04-P2增量与ACL.md) 一致：

```text
u32 version = 1
N × 20B: [type_tag][perms][inherit][id][reserved]
```

- 读取：`getxattr(dir, "system.trim_acl", ...)`，缺失则回落 POSIX mode；
- 解析：复用 `perm.c` 的位定义，抽成 `acl_parse()`；
- 组：`getgrouplist(uid)`，不能拿扫描进程自身组判断（现有注释已强调）；
- 版本：`version != 1` 视为不可解析 → 该目录 deny（fail-closed），并记日志。

**为什么以 xattr 为主，而不是飞牛 API：**

1. 与内核 `trimacl` 挂载语义同源，不会出现「API 说可读、内核拒绝」；
2. 扫描在 root 下离线可跑，不依赖 API 端口/token/网关；
3. 每条目录一次 xattr 的系统调用远低于一次 HTTP；
4. 飞牛版本升级时 xattr 格式比私有 API 更稳定（已有实测记录）。

**落地前先验证**：在真机执行 `trimacl file /vol1/@team/<team>` 与子目录，确认团队 ACL
确实落在 `system.trim_acl`。若某些版本只把团队 ACL 存在 `filestor` 数据库，则增加
`aclSource: "filestor"` 适配器（接口与第 9 节 ACL 适配器一致），但默认仍以 xattr 为准，
避免把 API 变成单点。

### 4.3 账号与团队（有哪些人）

| 数据 | 来源 | 说明 |
|---|---|---|
| 用户清单 | `/etc/passwd`（uid ≥ 1000）+ `scope.json.principals` | 扫描主体表；可用配置显式追加/排除 |
| 组清单 | `/etc/group` + `getgrouplist()` | 解释 `A_GROUP` 条目 |
| 管理员 | `Administrators` 组（gid 可配置） | 仅用于 UI 的 `all=1`；扫描按 ACL，不做特权放行 |
| 团队清单 | 可选：fnOS `filestor` / `accountsrv` API，或 `scope.json.teamPaths` | 只用于「找团队根」，不用于逐目录鉴权 |

飞牛 API 可作**交叉校验**（例如 `getAclByFiles` 返回的 permset 与 xattr 不一致时告警），
但扫描路径不依赖它。这样 API 挂掉、升级、鉴权变更都不会影响检索。

### 4.4 配置文件 `scope.json`

位置：`$TRIM_PKGVAR/scope.json`（与 `settings.json` 同目录；注意不是 `idx/` 里面），
管理员可写，0600。
完整示例见附录 A。它负责四件事：

1. **覆盖**：某 uid 追加/排除目录（仍受 ACL 上限约束）；
2. **远程存储**：provider 类型、挂载点、ACL 适配器、owner；
3. **测试**：`aclSource: "json"` 指向 fixture，CI 无需 root/xattr；
4. **策略**：`scanMode`、`isolatedUsers`、`teamPaths`、`systemDeny`。

### 4.5 缓存与失效（epoch）

```text
acl_epoch  = max(hash(xattr 扫描代次), mtime(/etc/passwd), mtime(/etc/group),
                 mtime(scope.json), remote mount_epoch)
```

- 快照头、视图文件都记录 `acl_epoch`；
- 请求时若 `view.acl_epoch != current` → 先尝试增量刷新；失败则**退回实时 ACL 过滤**
  （慢但正确），绝不使用过期视图放行；
- `FAN_ATTRIB`（0x8）落在目录上 → 标脏该目录子树，去抖 2s 后重算掩码；
- 团队/用户变更没有可靠 inotify 时，靠 `/etc/passwd`、`/etc/group` mtime + 6 小时对账兜底。

## 5. 权限映射

### 5.1 飞牛对象 → 路径 → 玄览语义

| 飞牛界面 | 实际路径 | 玄览处理 |
|---|---|---|
| 我的文件 | `/volN/<uid>` | 家目录根；属主读/穿越放行（`under_own_home`） |
| 团队文件 / 团队文件夹 | `/volN/@team/<team>` | 一等扫描根；按 ACL 逐目录求值 |
| 团队回收站 | `/volN/@team/<team>/.@#local/trash` | 硬排除 |
| 共享文件夹 | `/volN/<name>` | 普通一级目录，按 ACL |
| 应用文件 | `/volN/@appshare/...` | 默认排除（可配置） |
| 系统目录 | `/volN/@appdata`、`@apphome`、`@appcenter` 等 | 硬排除 |
| 远程挂载 | `/vol02/<uid>-<n>-<hash>` | provider=remote，默认 owner-only |
| 外接存储 | `/vol00/<label>` | provider=usb，默认仅管理员 |
| Docker / VM | `/volN/docker`、`/volN/vm` | 按 ACL；通常只有 root，自然被 L1 剪掉 |

> 版本差异：团队空间目录名在前端资源里是 `@team`，团队回收站是 `.@#local/trash`。
> 若某些版本用普通目录承载「团队文件夹」，在 `scope.json.teamPaths` 里显式列出即可，
> 扫描器不把命名写死。

### 5.2 ACL 位 → 玄览动作

| ACL 位 | 已知值 | 含义 | 玄览用途 |
|---|---|---|---|
| `r` | `0x0004` | 读数据 / 列目录 | **搜索可见、列目录** |
| `x` | `0x0001` | 执行 / 进入目录 | **祖先穿越**；目标目录也需 x |
| `w` | `0x0002` | 写数据 / 建文件 | 文件操作（现有） |
| `p` | `0x0008` | 追加 / 建目录 | 文件操作（现有） |
| `D` | `0x2000` | 删除子项 | 文件操作（现有） |
| `a` / `A` | `0x0100` / `0x0200` | 读/写属性 | 暂不参与检索 |
| `e` / `E` | `0x0040` / `0x0400` | 读/写扩展属性 | 暂不参与检索 |
| `c` | `0x0080` | 读 ACL | 暂不参与检索（ACL 变更走 epoch） |
| `d` / `C` / `o` | 未实测 | 删除自身 / 写 ACL / 取得所有权 | 文件操作，不参与检索 |

> 以 [04-P2增量与ACL.md](04-P2增量与ACL.md) 与 `trimacl -m` 实测为准；未实测的位不要猜数值。
> 检索只依赖两条：**列目录看 `r`，走到子目录看 `x`**。

### 5.3 求值规则（必须与 `perm.c` 完全一致）

1. 目标目录自身有 ACL → 用自身条目；本目录有 ACL 但没有任何条目命中该 uid → **拒绝**，
   不再向上找。
2. 自身无 ACL → 逐级向上找最近带 ACL 的祖先，只采纳 `inherit & dir` 的条目。
3. 都没有 → 回落 POSIX mode 的读位。
4. **deny 覆盖 allow**（同一位）。
5. `everyone` 条目在家目录内受 `strict_home` 约束（只放行穿越，不放行读）。
6. `owner` 条目按目标 inode 属主判断。
7. 卷根 `/volN` 的 mode 0000 是飞牛特例，**不参与穿越判定**。
8. 家目录属主对 `/volN/<uid>` 子树直接放行读/穿越（不授写）。
9. `0x4000` 是「排除继承」边界标记，不当作 ACE。

批量求值必须逐条对齐以上语义；第 11.3 节的**差分测试**是验收硬门槛：
对 fixture 的每个目录、每个主体，`mask.read(d,u) == perm_dir_listable(u,d)`，
`mask.traverse(d,u) == perm_check(u,d,X,1)`。

### 5.4 用户动作 → 需要的权限

| 动作 | 判定 |
|---|---|
| 搜索结果出现 | 父目录 `r+x`（且在 scope 内） |
| 目录列表出现 | 该目录 `r+x` |
| 打开/下载/预览 | 父目录 `r+x`，目标文件 `r`；另做实时 ACL 复核 |
| 复制/移动到目标 | 目标目录 `w+x`（现有 `perm_dir_writable`） |
| 删除/重命名 | 父目录 `w+x`（现有 `perm_parent_writable`） |

### 5.5 团队文件夹的路径规则

```text
/volN/@team                      ← 容器：记结构节点（scope_id=0），不展示
/volN/@team/<team>               ← 团队根，按 ACL 决定是否记录
/volN/@team/<team>/**            ← 普通 ACL 继承
/volN/@team/<team>/.@#local/**   ← 回收站，硬排除
```

- `@team` 是隐藏名，但它是**显式白名单容器**：扫描器允许进入 `@team`，只跳过其它 `@` 目录；
  `@team` 自身作为结构节点记录（`scope_id=0`），以便子路径的 parent 链完整；
- 团队根不要求「所有人可读」；只要存在**任意主体**可穿越，就进入扫描（否则 L1 跳过）；
- 团队名含 `/`、`..`、控制字符 → 视为异常路径，跳过并告警。

## 6. 扫描作用域（目录白名单）

### 6.1 数据结构

```c
#define XL_SCOPE_MAX 512

typedef struct {
    char     path[PATH_MAX];   /* 规范化绝对路径，无结尾 '/' */
    uint16_t source;           /* AUTO_HOME / AUTO_TEAM / AUTO_SHARE /
                                  AUTO_REMOTE / MANUAL / CONFIG / HARD_DENY */
    uint8_t  deny;             /* 1 = 排除 */
    uint8_t  recursive;        /* 1 = 含子树（当前恒为 1，预留 maxdepth） */
} xl_scope_ent;

typedef struct {
    uid_t        uid;
    xl_scope_ent ent[XL_SCOPE_MAX];
    int          n;
    uint32_t     acl_epoch;
    uint32_t     flags;        /* 1=已合并手动配置 2=来自严格隔离 */
} xl_scan_scope;
```

### 6.2 默认作用域的生成

```text
resolve_scope(uid):
    sc = []
    for vol in volumes:
        if perm_dir_listable(uid, "/vol{vol}/{uid}"):      # 家目录
            add(sc, "/vol{vol}/{uid}", AUTO_HOME)
        if teamSpaces:
            for team in list("/vol{vol}/@team"):
                root = "/vol{vol}/@team/{team}"
                if perm_dir_listable(uid, root):
                    add(sc, root, AUTO_TEAM)
                else:
                    # 父不可列、子被单独授权：最多下探 2 层（与 handle_acl_list 对齐）
                    for sub in granted_children(uid, root, depth=2):
                        add(sc, sub, AUTO_TEAM)
        for name in list("/vol{vol}"):
            if is_home(name) or is_system(name) or name in ("@team", "@appshare"): continue
            p = "/vol{vol}/{name}"
            # includeShared 默认 false（保持 0.8.x 行为：共享盘需手动勾选）
            if includeShared and perm_dir_listable(uid, p): add(sc, p, AUTO_SHARE)
    for m in mounts:
        if provider_acl_allows(m, uid): add(sc, m.mountpoint, AUTO_REMOTE)
    merge_manual(sc, "scope-{uid}.json")     # 用户自己勾选，只收窄
    merge_config(sc, "scope.json", uid)      # 管理员覆盖，deny 优先
    hard_deny(sc, system_paths, trash)       # 最后压一层，不可被覆盖
    return sc
```

要点：

- `scope_default()` 现在只收「家目录 + granted」，团队根属于「可列但非 granted」，
  必须新增 `AUTO_TEAM` 类别并纳入默认范围；
- 普通共享盘保持现状：`includeShared=false` 时不自动纳入，用户可在设置里勾选；
  这样既不会把 everyone 共享盘灌进每个人的默认结果，也不影响 ACL 上限；
- 团队根是否可列由 `perm_dir_listable()` 决定，**不依赖团队名单 API**；
- 生成结果缓存 `(uid, acl_epoch)`，避免每次 `/api/me` 重算；
- 这份 auto scope 用于**扫描计划 / isolated 模式 / 设置页默认值**；shared 模式的查询默认
  不再额外按路径收窄（否则会把 everyone 共享盘从老用户结果里拿掉），用户保存过
  `scope-<uid>` 后才按手动范围收窄。

### 6.3 合并与匹配

> 下式用于**扫描白名单 / isolated 模式 / 设置页展示**；shared 查询只叠加 manual 收窄，
> ACL 上限由视图负责（见 8.2）。

```text
effective_allow = (ACL 允许集合) ∩ (auto ∪ manual ∪ config_allow)
effective_deny  = hard_deny ∪ manual_deny ∪ config_deny
visible(p) = any_allow_prefix(p) and not any_deny_prefix(p)
```

- 前缀匹配按**路径分量边界**：`/vol1/10` 不匹配 `/vol1/1000`；
- 同一层取最长匹配；跨层 deny 永远优先；
- `manual`/`config` 的 allow 不能越过 ACL：解析阶段丢弃 ACL 不可读的条目并记日志；
- 排序：短前缀在前，便于扫描计划合并；deny 单独存。

### 6.4 持久化

| 文件 | 内容 | 兼容 |
|---|---|---|
| `scope-<uid>.txt`（现有） | 每行一个路径，`!` 开头为排除 | 继续读 |
| `scope-<uid>.json`（新） | `{version, aclEpoch, allow[], deny[], source}` | 优先读；TXT 保留只读兼容 |

## 7. 跳过逻辑（实现步骤）

### 7.1 两个位图

对目录 `D` 与主体集合 `P`：

```text
traverse(D) = { u | traverse(parent(D), u) && own_x(D, u) }   # 主体位图
read(D)     = { u | traverse(D, u) && own_r(D, u) }           # 主体位图

L1（物理跳过）：traverse(D) == 0        # 所有主体都进不去 → 整棵不扫
L2（用户跳过）：u ∉ read(D)             # 该用户视图中没有 → 不参与其查询
```

- `own_*` 按第 5.3 节求值（自身 ACL → 继承 → POSIX）；
- 卷根：`traverse(/volN) = 全体`，`read(/volN) = ∅`（特例）；
- 家目录属主：`own_*` 直接为 1（读/穿越，不含写）；
- 注意：**单个用户 `traverse(D, u)=0` 不是 L1**；只要还有别的用户能进，子树仍会为那些用户扫描。
  真正 L1 是 `traverse(D)` 位图为空。

### 7.2 十步跳过流程

```text
scan_dir(path, depth, parent_state):
 1. provider 健康？挂载 epoch 一致？        否 → 记 stale，跳过
 2. realpath + 长度/`..`/NUL 检查            失败 → 跳过
 3. 必须位于某个已注册挂载点内                否 → 跳过
 4. 命中硬排除（系统目录/回收站/隐藏杂项）     是 → 跳过（不记录）
 5. 挂载点穿越检查（st_dev != 根设备）         是 → 未注册 provider 则跳过
 6. 计算 tm = parent.tm & own_x                tm == 0 → **整棵跳过（L1）**
 7. 计算 rm = tm & own_r                       rm == 0 → 记结构节点（scope_id=0），继续下探
 8. 名称规则：隐藏/系统杂项                    是 → 跳过（@team 例外）
 9. 记录目录：scope_id = intern(rm)；`@team` 容器固定 scope_id=0
10. 递归子项；文件仅在 parent.rm != 0 时记录 scope_id = intern(parent.rm)
```

补充约束：

- 深度上限 512，名字长度 ≤ 255；
- 符号链接不跟随（`lstat`/`d_type`），`realpath` 只用于根与守卫；
- 子挂载不递归，除非该挂载已注册为 provider；
- 单目录 `EACCES`：若掩码显示有人可读 → 记「异常」并跳过，不中断整卷；
- 预算：单卷最多 2000 万条、单用户视图最多 500 万条；超限置 `partial=true`。

#### 7.2.1 决策示例（fixture，A=1000 的投影 + 全局 L1）

| 路径 | A 的 `tm` | A 的 `rm` | 全局 L1？ | 动作 |
|---|---|---|---|---|
| `/vol1` | 1 | 0 | 否 | 卷根特例，不记录 |
| `/vol1/1000` | 1 | 1 | 否 | 记录（家目录） |
| `/vol1/1001` | 0 | 0 | **否**（B 可进） | A 视图无；索引里仍有 B 的记录 |
| `/vol1/共享` | 1 | 1 | 否 | 记录（默认 scope 不收，需勾选） |
| `/vol1/@team` | 1 | 1 | 否 | 容器：记 `scope_id=0` 结构节点，不展示 |
| `/vol1/@team/研发` | 1 | 1 | 否 | 记录 |
| `/vol1/@team/研发/公开` | 1 | 1 | 否 | 记录（everyone r） |
| `/vol1/@team/研发/机密` | 1 | 0 | 否 | 记 `scope_id=0` 结构节点、继续下探；文件因父 `rm=0` 不记录 |
| `/vol1/@team/财务` | 0 | 0 | 否（B 可进） | A 视图无；B 的索引有 |
| `/vol1/@team/废弃` | 0 | 0 | **是**（deny everyone） | 整棵不 open、不记录 |
| `/vol1/docker` | 0 | 0 | **是**（root only，主体表不含 0） | 整棵不 open、不记录 |
| `/vol1/@appdata` | — | — | 硬排除 | 连 `open()` 都不做 |

> 关键区别：`tm=0` 对**单个用户**只意味着「不进入他的视图」；只有 `traverse(D)` 位图为空
> 才是“谁都用不了”的 L1。`tm=1, rm=0` 是「可穿越但不可列」：本级记 `scope_id=0`
> 结构节点（父链需要），仍要下探，以便找到被单独授权的子目录；其下文件不记录。

### 7.3 批量 ACL 求值（性能关键）

逐目录、逐用户调用 `perm_dir_listable()` 会退化为 `O(dirs × users × depth)` 次 xattr。
正确做法是**一次遍历、一次 xattr、一次解析，算出全部主体**；同时把「最近祖先 ACL」
作为状态向下传，避免每层重新向上找：

```c
typedef struct {
    const xl_acl *acl;   /* 最近一个对当前主体「有判定权」的祖先 ACL；NULL=无 */
} inh_state;

/* 每个目录：一次 getxattr，解析后对每个主体算 own_r/own_x */
dir_state eval_dir(const char *path, const inh_state *parent, principal *ps, int n) {
    acl = acl_load(path);                    /* xattr 或 json fixture */
    for each u:
        if (under_own_home(u, path)) {
            own_r = own_x = 1;               /* 家目录属主：只读/穿越 */
        } else if (acl) {
            hit = 0; g = d = 0;
            for ace in acl:                   /* 自身判定：所有 ACE 都算 */
                if (ace.excl) continue;
                if (!ace_matches(ace, u)) continue;
                hit = 1; ace.deny ? d |= ace.perms : g |= ace.perms;
            own_r = hit && !(d & R) && (g & R);
            own_x = hit && !(d & X) && (g & X);
            /* 无命中 → 0；且不再向上找（与 eval_one 一致） */
        } else if (parent->acl) {
            /* 无自身 ACL：用最近祖先 ACL 的 inherit&dir 条目；
               无命中同样返回 0（eval_ancestors 命中该 ACL 即停止） */
            own_r = inherit_bit(parent->acl, u, R);
            own_x = inherit_bit(parent->acl, u, X);
        } else {
            own_r = posix_read(u, path); own_x = posix_exec(u, path);
        }
        tm[u] = parent_tm[u] && own_x;
        rm[u] = tm[u] && own_r;
    /* 子目录的最近祖先 ACL：有自身 ACL 就替换，否则继续向上传 */
    child = { .acl = acl ? acl : parent->acl };
    return {tm, rm, child};
}
```

> 关键点：祖先 ACL 是「按用户匹配」的，不能只缓存一组 grant/deny 位。把 ACL 节点指针
> 往下传、对每个用户现算 `inherit_bit()`（`matched==0` 时返回 0），才能与
> `eval_one()` + `eval_ancestors()` 的语义逐条一致。差异由差分测试兜底。
>
> 主体数 ≤ 512 用 8×u64 位图；超过则按页分片（每页 512 主体、独立 scope 表），
> 或对超出部分退化为实时 ACL 过滤。

### 7.4 视图生成（L2）

```text
build_views(vol):                       # 每个卷的 scope_id 空间独立
    for u in principals:
        bits = bitset(vol.scope_count)
        for sid in 0..vol.scope_count-1:
            if mask_read(vol.scope_masks[sid], u): bits.set(sid)
        write view-<vol>-<uid>.bin {magic, vol, uid, acl_epoch, scope_count, bits}
```

- 视图很小：`scope_count` 通常几百到几千（同权限目录共享一个 id），8KB 以内；
- 未在主体表中的新用户：查不到视图 → **退回实时 ACL 过滤**，并排队补建；
- 用户被禁用/删除：视图文件按 mtime 清理，请求 401。

### 7.5 边界场景

| 场景 | 处理 |
|---|---|
| 父目录不可列、子目录显式授权 | 父记 `scope_id=0` 结构节点并继续下探；子记录并可见（会暴露祖先路径名，见 12.2） |
| `deny` + `allow` 同用户 | deny 胜 |
| `exclude inheritance` 边界 | 边界以下不继承祖先授权 |
| 家目录 `everyone` 授权 | `strict_home=1` 时忽略读，只留穿越 |
| 0600 文件在可列目录中 | 默认只出现在结果、打开时拒绝；`hideUnreadableFiles=true` 可隐藏 |
| 符号链接指向他人目录 | 不跟随；`realpath` 越界即跳过 |
| 跨挂载点 | 未注册 provider 不递归 |
| 远程挂载掉线 | 保留旧索引并标 `stale`；超过 TTL 隐藏；不删数据 |
| 权限刚改、视图未刷新 | 服务端实时复核拒绝；视图后台重建 |

## 8. 索引 v3 与查询

> **实现状态（重要）**：本节 8.1–8.3 是**未来优化设计**，当前代码尚未实现。
> 当前 `XL_VERSION` 仍为 2，没有 `rec_scope`/`scope_masks`/每用户 view；
> `shared` 模式仍按查询期 ACL 复核，`isolated`/`hybrid` 使用 `idx/units/<unit>/` 独立快照。
> 单元路由/独立扫描/增量/修复见 §17（P2–P9）。不要把本节当作已交付能力。

### 8.1 快照扩展（不动 128B 头）

保持 `xl_hdr` 128 字节不变，`version=3`（同步把 `XL_VERSION` 提到 3，
`snapshot_open()` 接受 2/3），复用 `reserved2` 指向扩展块：

```c
typedef struct {
    uint32_t magic;          /* 'XSCP' */
    uint32_t scope_count;
    uint32_t principal_count;
    uint32_t acl_epoch;
    uint64_t masks_off;      /* scope_masks：scope_count × 64B 位图 */
    uint64_t rec_scope_off;  /* uint16[rec_count] */
    uint64_t principals_off; /* 可选：uid 列表，调试用 */
    uint64_t reserved;
} xl_scope_ext;              /* 4KB 对齐 */
```

- `rec_scope[i]`：记录 i 的可见性 id；目录用自身 `rm`（结构节点为 0），文件用父目录 `rm`；
- `scope_id` 为 `uint16`，上限 65535 个不同掩码；`intern()` 从 1 开始，0 永久保留给结构节点；
- `scope_masks[sid]`：512 位主体位图（8×u64）；`scope_masks[0]` 固定全 0；
- `scope_id=0` 是「结构节点 / 空掩码」，任何视图都不含它；`rm == 0` 但可穿越的目录、
  以及 `@team` 容器用它记录，保证子记录的 parent 链能还原绝对路径；
- 旧 v2 索引：可读，但无 scope → 退回逐条 ACL 过滤，并提示重建。

存储开销（500 万条）：

| 段 | 大小 |
|---|---|
| `rec_scope` | 10 MB |
| `scope_masks`（按 2k 个 scope 估） | 128 KB |
| 每卷每用户视图 | ≤ 8 KB |
| 合计 | 约 +2% 索引体积 |

### 8.2 查询流程

```text
handle_search(uid, q):
    view = view_load(vol, uid)                  # 该卷的 ACL 投影；mmap，缺省则重建/回退
    sc   = scope_load(uid)                      # 仅用户手动保存的收窄；未保存(-1)则不额外过滤
    hits = query_hits(...)                      # 不变
    for each hit:
        path = snap_path(hit)
        if live_is_deleted(path): continue
        if sc and !scope_allows(sc, path): continue        # 手动收窄
        if view:
            sid = rec_scope[hit]
            if !view_test(view, sid): continue              # L2，O(1)
        else if !perm_dir_listable(uid, parent(path)):
            continue                                        # 回退：实时 ACL
        if strictFile && !perm_mode_readable(uid, path): continue
        emit
```

- 多卷时每卷各一份视图与 `scope_id` 空间，查询按卷分别加载、合并排序；
- 两条过滤各司其职：`view` 是 ACL 上限（防止越权），`scope` 是用户自己的收窄（少看一点）；
- 不再对每条命中做 `perm_dir_listable()`（读 xattr）；
- 增量命中 `live_query()` 不在快照里，必须用父目录实时 ACL 判定后再输出；
- 目录列表 `/api/dir`、缩略图、预览、下载仍保留实时复核（第 2 节不变量 3）；
- `total` 仍可能为近似值（裁剪后的候选数），保持现有 `approx` 语义。

### 8.3 增量与对账

- `live.c` 新增 `FAN_ATTRIB`：目录属性/ACL 变化 → 标脏子树；
- 新文件：父目录 `scope_id` 直接复用；父目录 `tm == 0` 则忽略事件；
- ext4 裸设备读（`fsreader_ext4_scan()`）不解析 xattr：启用 scope 模式时强制走目录遍历
  （`build_one()` 里置 `no_raw=1`），否则权限掩码会失真；
- 删除：墓碑逻辑不变；
- 权限变化无法可靠捕获时，6 小时全量对账重建掩码与视图；
- 对账时先构建新索引与视图，全部 `.tmp` 就绪后原子 rename、再整体切换，避免读到半成品。

### 8.4 严格隔离模式

```text
idx/
  vol1.idx                 # shared 模式
  units/
    u1000/vol1.idx         # isolated 模式，仅含该用户可穿越子树
    u1002/vol1.idx
```

- 对 `isolatedUsers` 中的用户，Walker 只保留 `tm[u] != 0` 的分支，其余**不 open**；
- 查询只读该用户自己的索引，不需要 view 过滤；
- 代价：每用户一次全盘遍历；建议只对团队文件夹/敏感用户开启，并复用目录项缓存；
- 扩展块写 `owner_uid`，服务启动时校验文件属主，防串读。

## 9. 远程挂载接口

### 9.1 Provider 抽象

```c
typedef struct xl_storage xl_storage;

struct xl_storage {
    const char *id;              /* "vol1" / "smb-1004-a1" */
    const char *kind;            /* local | smb | nfs | webdav | s3 | usb */
    char        mountpoint[PATH_MAX];
    uint32_t    mount_epoch;
    int         flags;           /* READONLY / XATTR_ACL / OWNER_ONLY / ADMIN_ONLY */

    int (*walk)(xl_storage *s, const char *root, xl_walk_cb cb, void *ud);
    int (*acl_mask)(xl_storage *s, const xl_principal *ps, int n,
                    const char *path, int is_dir, xl_umask *out);
    int (*stat)(xl_storage *s, const char *path, struct stat *st);
    int (*health)(xl_storage *s, char *msg, size_t cap);
    int (*watch)(xl_storage *s, xl_watch_cb cb, void *ud);   /* 可为 NULL */
};
```

- `local`：`getdents64` + `system.trim_acl`，复用 `scan.c`/`perm.c`；
- `remote`：`walk` 可复用同一套目录遍历（CIFS/NFS 支持 readdir），`acl_mask` 走适配器；
- `watch` 为空时由 30s 挂载表轮询 + 6h 对账兜底；
- 失败语义：`health` 失败 → 该存储整体 `stale`，扫描任务跳过，查询按 TTL 隐藏。

### 9.2 ACL 适配器

| 适配器 | 判定 | 适用 |
|---|---|---|
| `xattr` | `system.trim_acl`，与本地一致 | ext4/ZFS、支持 xattr 的 NFSv4 |
| `owner` | 仅挂载 owner uid + 管理员可读 | fnOS 远程挂载 `/vol02/<uid>-*`（CIFS 默认） |
| `config` | `scope.json.storages[].aclMap` 显式路径 → 主体 | WebDAV/S3、无 POSIX ACL 的共享 |
| `posix` | mode 位 | 兜底 |
| `admin` | 仅管理员 | `/vol00` 外接盘 |

fnOS 远程挂载目录名带 uid（实测 `/vol02/1000-0-d35695fe`），可自动解析 owner；
若同一共享被多个用户各自挂载，则各自是独立挂载点，天然隔离，不需要身份映射。

### 9.3 注册与生命周期

```json
"storages": [
  {"id":"vol1","kind":"local","mountpoint":"/vol1","acl":"xattr"},
  {"id":"smb-1004","kind":"smb","mountpoint":"/vol02/1004-0-a1b2c3d4","acl":"owner"},
  {"id":"usb-sandisk","kind":"usb","mountpoint":"/vol00/SanDisk","acl":"admin"}
]
```

- 启动时枚举 `/proc/self/mounts`，匹配配置 → 创建 provider；
- 未配置的挂载点默认不扫描（安全默认），日志提示；
- 30s 轮询挂载表：新增 → 入队建索引；消失 → 标 stale；路径变化 → 重建；
- 掉线不删索引；`stale` 超过 24h 或重新挂载后重建；
- 远程扫描使用独立任务队列，限并发 1，单目录超时 10s，失败重试 2 次。

### 9.4 扫描伪代码（远程）

```text
scan_storage(s):
    if !s->health(msg): mark_stale(s); return
    if s->flags & OWNER_ONLY:
        principals = [owner(s)] + admins
    else:
        principals = all_principals()
    walk(root):
        for entry in readdir(root):
            if skipped(entry): continue
            out = s->acl_mask(ps, dir, is_dir)
            tm = parent_tm & out.traverse
            if tm == 0: skipped++; continue
            emit(entry, scope_id(tm & out.read))
            if dir: walk(path)
```

远程 provider 的 `acl_mask` 可以一次性返回整棵子树（如 owner-only），Walker 短路，
避免逐目录系统调用。

## 12. 观测、风险与回滚

### 12.1 指标

```text
xuanlan_scope_resolve_ms{uid}
xuanlan_mask_eval_us_per_dir
xuanlan_skipped_subtrees_total
xuanlan_view_stale_seconds{vol,uid}
xuanlan_view_fallback_total          # 回退实时 ACL 的次数
xuanlan_remote_errors_total{storage}
xuanlan_remote_stale{storage}
```

### 12.2 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 批量求值与 `perm.c` 语义漂移 | 越权/漏搜 | 差分测试 + 金标用例进 CI |
| 每目录 xattr 拖慢构建 | 对账超时 | 仅目录读 xattr；POSIX 快路径；scope 模式强制走目录遍历（关 raw ext4） |
| 权限变更未及时反映 | 越权展示 | FAN_ATTRIB + epoch + 服务端复核 |
| 主体数 > 512 | 位图溢出 | 分页/回退实时 ACL |
| 新用户无视图 | 搜不到 | 首次请求补建；期间实时过滤 |
| 远程挂载抖动 | 构建卡死 | 超时、独立队列、stale、不删索引 |
| 祖先路径名泄露 | 隐私 | 子目录显式授权场景可配 `hideAncestors` |
| 团队目录命名随版本变化 | 漏扫 | `teamPaths` 配置 + 启动探测 + 文档 |

### 12.3 回滚

- 关闭 `XL_SCOPE`，删除 v3 索引，按 v2 重建；
- 保留 `scope-<uid>.txt` 读取路径，UI 可退回旧「检索范围」；
- 远程 provider 全部失效时只影响对应挂载，不影响本地卷。

## 14. UI 交互补充（鼠标与视频）

> 本节记录本次交互调整的界面约定，落点 `ui/index.html`；设置持久化在
> `src/httpd.c` 的 `handle_settings_get()` / `handle_settings_post()`。

### 14.1 鼠标打开策略

默认值：**文件夹单击打开，文件/图片双击打开**。设置项为两个独立字段，便于分别调整：

| 设置项 | 字段 | 可选值 | 默认 |
|---|---|---|---|
| 文件夹打开 | `clickFolder` | `single` / `double` | `single` |
| 文件 / 图片打开 | `clickFile` | `single` / `double` | `double` |

判定顺序（`clickModeOf(it)`）：

1. **触屏优先**：`pointer:coarse` 时单击直接打开，忽略上述设置（保持手机端单手操作）；
2. 点击复选框、`⋯`、复制按钮等交互控件时只处理控件，不触发打开；
3. 文件夹按 `clickFolder`，文件/图片按 `clickFile`；
4. 仅当模式为 `double` 时 `dblclick` 才打开；`single` 模式下 350ms 内的第二次点击被抑制，
   避免系统双击事件把同一个文件打开两次；
5. 打开动作本身不再弹确认框；「不支持预览、是否下载」的询问只针对格式能力，不属于打开确认。

设置持久化：

```json
{
  "settingsVersion": 3,
  "openIn": "embed",
  "clickFolder": "single",
  "clickFile": "double"
}
```

- 字段缺失：沿用上一版 `settings.json` 的值，升级不重置用户选择；
- 非法值：回落到默认（文件夹 `single`、文件 `double`），并记录一次设置保存；
- 触屏路径只改变当前点击行为，不写回服务器设置，桌面端仍按保存的 click* 值工作。

### 14.2 视频控制条与快捷键

实现要点：

- 视频不再塞进 `<iframe>` 让浏览器画原生控制条，而是 `openwin` 内的独立
  `<video id="vvideo">` + 自定义 `.vbar`；原生 `controls` 属性关闭，避免双层控制条；
- 控制条绝对定位在画面底部，**默认随鼠标进入显示、鼠标离开 `#videoview` 立即隐藏**；
  播放中鼠标静止 2.6s 自动隐藏；暂停时鼠标在内保持可见，离开仍然隐藏；
- 快捷键仅在视频视图打开、且焦点不在 `input/textarea/select/button/contenteditable`
  时生效；设置面板打开时不拦截：
  - `Space`：暂停/播放，`preventDefault` 防止页面滚动；
  - `ArrowLeft`：后退 5 秒；
  - `ArrowRight`：前进 5 秒；
  - 进度限制在 `[0, duration]`；转码流 `duration` 为 `Infinity` 时按当前时间相对调整；
- 关闭子窗口、打开 PDF/iframe 或切换到其它文件时停止播放并清空 `src`，避免后台继续解码；
- `openIn=window` 时由浏览器原生播放器接管，自定义控制条与快捷键不生效（页面无该视图）；
- 打开方式为「在线预览 / 文档服务」时，视频由外部应用 iframe 播放，控制条与快捷键归外部应用，
  本节的约定只覆盖内置播放器（浏览器直接打开或服务端转码）。

## 15. 三种扫描模式与隔离存储方案（决策稿）

### 15.1 模式定义

管理员在后台三选一，默认 `shared`：

| 模式 | 索引单元 | 扫描范围 | 查询入口 | 适用 |
|---|---|---|---|---|
| `shared` | 每卷 1 份 | 所有主体并集，L1 + L2 视图 | 共享索引 + 用户视图 | 默认；只要求“搜不到/打不开” |
| `isolated` | 每用户 1 份 | 该用户 `ScanScope`，物理跳过 | 该用户自己的索引 | 全员强隔离；用户少、数据可控 |
| `hybrid` | 共享索引 + 按组/用户的隔离单元 | 共享用户走并集；隔离组按组扫 | 按用户归组路由 | 大多数团队：默认共享，敏感组隔离 |

`hybrid` 是主推的折中：

- 默认所有用户走共享索引；
- 管理员把**用户组**放进 `share` 或 `isolated` 分类；
- `isolated` 分类里的组按组独立扫描、独立索引；
- **组不在任何分类时回退 shared**；
- 共享索引始终保留，作为 share 组与未分类用户的兜底；
- 隔离用户只读自己的隔离索引，**不回退共享**（否则隔离失效，fail-closed）。

### 15.2 配置项与默认值

```json
{
  "scanMode": "shared",
  "shareGroups": [],
  "isolatedGroups": [],
  "shareUsers": [],
  "isolatedUsers": []
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `scanMode` | `shared` / `isolated` / `hybrid` | `shared` | 全局模式，仅管理员可改 |
| `shareGroups` | gid 数组 | `[]` | hybrid 下归入共享索引的组 |
| `isolatedGroups` | gid 数组 | `[]` | hybrid 下按组独立扫描的组 |
| `shareUsers` | uid 数组 | `[]` | 用户级显式覆盖为共享 |
| `isolatedUsers` | uid 数组 | `[]` | 用户级显式覆盖为隔离 |

以上字段可写在 `scope.json` 顶层；管理端设置页保存到 `scanmode.json` 覆盖层
（只覆盖模式与四个分类数组，不改 `scope.json` 的 teamPaths/storages/overrides 等高级字段）。
两者同时存在时 `scanmode.json` 优先；只有管理员可写。

- 组用 **gid** 存，界面显示 `gid + 名称`；组改名不影响索引归属。
- 用户/组不存在或已删除：配置保留但解析时忽略，并写日志。
- `isolated` 模式忽略分类表：每个用户一个 `u<uid>` 单元。
- `shared` 模式忽略分类表：所有人走共享索引。

### 15.3 组分类与判定规则（hybrid）

对请求 uid，按以下顺序判定，**先命中先返回**：

```text
1. uid ∈ isolatedUsers        → 单元 u<uid>
2. uid ∈ shareUsers           → shared
3. uid 属于任一 isolatedGroups → 该用户所有 isolated 组的单元（通常 1 个，多个取并集）
4. uid 属于任一 shareGroups     → shared
5. 其它                        → shared（未分类回退）
```

补充规则：

- **显式用户覆盖优先于组**：用户在 `shareUsers` 里、但同时属于 `isolatedGroups`，仍走 shared；
  反之在 `isolatedUsers` 里则强制隔离。
- **隔离优先于共享组**：用户同时属于 isolated 组和 share 组，且没有用户级覆盖时，走隔离。
- **多隔离组**：用户属于多个 isolated 组时，查询加载这些组的全部单元并合并去重；
  扫描仍按组各建一份，不额外生成“个人合并索引”。
- **组不在分类**：成员回退 shared；这是“默认 shared”的落点。
- **单元命名**：`shared`、`u<uid>`、`g<gid>`；组单元按 gid 升序稳定输出。
- **空组/无成员组**：不建索引；配置保留。
- **成员变化**：组的成员快照写入 `unit.json`；`acl_epoch` 变化时重建该组单元，
  用户归属在查询时按当前 `getgrouplist()` 重新计算。

### 15.4 隔离存储：两种方案对比

#### 方案 A：单库多租户（one DB, tenant partition）

一个数据库文件（SQLite 或自研 DB），所有单元共库，用 `tenant_id` / 分区表隔离。

| 优点 | 劣势 |
|---|---|
| 共享数据只存一份，团队目录重叠时体积最省 | 所有租户名字仍在一个文件里，**物理隔离名不副实** |
| 单事务、单备份、单恢复点 | 任一查询漏加 tenant 条件就是越权 |
| 管理端可跨租户统计/审计 | 单库损坏/锁冲突影响全部用户 |
| 未来加 SQL 查询方便 | 需要引入 DB 引擎，现有 mmap 快照/trigram 要重写或双栈 |
| 一致性好，所有单元同一版本 | 大库 vacuum/compact/备份慢，写放大明显 |

#### 方案 B：每单元一份快照文件（同目录）

`idx/units/<unit>/<vol>.idx`，复用现有 `snapshot.c` 格式，按卷 mmap。

| 优点 | 劣势 |
|---|---|
| **物理隔离**：单份索引只含该单元可见路径，文件级 0600 | N 份重复数据，存储 N 倍 |
| 复用现有快照/查询/trigram，不引第三方依赖 | 单元多时目录/文件数量增加（通常 < 100） |
| mmap 零拷贝，启动与查询延迟最好 | 跨单元一致性要 `acl_epoch` + `unit.json` 管理 |
| `.tmp` + `rename` 原子替换，单单元损坏不影响别人 | 权限变更要重建对应单元，分钟级 |
| 备份/删除/迁移按单元操作，爆炸半径小 | 组间共享目录会重复存多份 |

> “每人一个独立 SQLite 文件”是方案 B 的变体：隔离性同 B，但多了 DB 引擎、连接/事务/文件头开销，
> 且现有查询层要重写。除非未来需要 SQL 复杂查询，否则不选。

#### 结论：选 B（组粒度快照文件）

理由：

1. 隔离模式的核心价值是**物理隔离**，A 方案先天不满足；
2. 玄览已有 mmap 快照和 trigram 查询，B 是复用而不是重写；
3. 单单元损坏/重建只影响该组，符合团队隔离的运维直觉；
4. 组粒度把 `N 用户` 降为 `K 权限组`，通常 K=2–5，重复存储可接受；
5. 文件级 0600 + 目录 0700，配合独立单元，安全边界清晰。

### 15.5 目录布局与元数据

```text
idx/
├── vol1.idx                     # 共享索引（shared / hybrid 的 share 组与未分类）
├── vol2.idx
└── units/
    ├── g9001/                   # 研发组，组内共享一份
    │   ├── unit.json
    │   ├── vol1.idx
    │   └── vol2.idx
    ├── g9002/                   # 财务组
    │   ├── unit.json
    │   └── vol1.idx
    └── u1004/                   # 用户级强制隔离（isolatedUsers / isolated 模式）
        ├── unit.json
        └── vol1.idx
```

`unit.json`：

```json
{
  "version": 1,
  "unit": "g9001",
  "kind": "group",
  "gid": 9001,
  "name": "研发",
  "members": [1000, 1002],
  "aclEpoch": 1730000000,
  "builtAt": 1730000000,
  "volumes": ["/vol1", "/vol2"],
  "format": "XLANIDX/3"
}
```

规则：

- 目录 0700，索引与 `unit.json` 0600；
- 构建到 `units/.tmp-<unit>/`，全部卷写完后 `rename` 为正式目录；旧目录保留到新目录就绪；
- 共享索引仍写 `idx/volN.idx`，hybrid 下**始终构建**；
- 隔离单元缺失/过期：该单元用户查询返回“索引未就绪”，**不回退共享**（fail-closed）；
- 共享用户查询只读 `idx/volN.idx`，不加载 `units/`；
- 多隔离组用户按 uid → gid 列表加载多个单元，合并结果并按路径去重。

### 15.6 管理员设置界面

后台「设置 → 扫描模式」：

| 控件 | 说明 |
|---|---|
| 模式 | 共享 / 隔离 / 混合；每个选项下方一行说明与成本 |
| share 组 | 多选组（gid + 名称）；仅 hybrid 显示 |
| isolated 组 | 多选组；仅 hybrid 显示 |
| 用户覆盖 | 可选，按 uid 加入 share/isolated；用于例外 |
| 生效预览 | 输入 uid 显示解析结果：单元、来源、是否回退 |

文案要点：

- 共享：**成本最低**；结果按 ACL 裁剪，但扫描进程会读所有可被任何人访问的目录；
- 隔离：**每人一份索引**，物理不读他人目录；构建/存储 N 倍，权限变更重建慢；
- 混合：默认共享；只有 isolated 组独立扫描；未分类组回退共享；共享索引始终保留；
- 冲突：用户级覆盖 > 组分类；隔离组 > 共享组；无分类 = 共享。

## 16. 数据库后端评估（MariaDB / PostgreSQL）

### 16.1 结论

**明确不引入 DB 后端；DB 仅作为未来可选分析副本，不作为检索路径。**

- 检索、ACL 判定、用户视图、隔离单元全部只走快照文件；
- 运行时不依赖 MariaDB/PostgreSQL，不引入连接池、账号、迁移和服务进程；
- 若未来需要报表/审计/跨维度分析，可由管理员**离线导出**快照到 PostgreSQL/MariaDB
  作为只读分析副本，**不回写、不参与搜索、不参与权限判定**；
- 数据库不会提高玄览的检索速度，也不会提高读并发；玄览的主负载是
  **批量建索引 + 大量只读检索**，与快照模型天然匹配。

### 16.2 为什么快照在检索上更快

| 环节 | 快照 + mmap | 数据库 |
|---|---|---|
| 查询路径 | 进程内指针 + trigram 倒排，无网络/无 SQL 解析 | 连接池 → SQL 解析 → 计划器 → 执行器 → 行返回 |
| 数据读取 | mmap 只读页，OS page cache 直接命中 | buffer pool / 页管理 / MVCC 可见性判断 |
| 索引形态 | 为“文件名子串”定制的定长块 trigram，约 1.3B/posting | 通用 B-tree/GIN/FULLTEXT，更大、更通用 |
| 中文子串 | 字节级 trigram，天然支持任意子串 | pg_trgm 对短词/中文索引膨胀；MariaDB ngram 是分词语义 |
| 启动 | mmap 即用，无恢复/回放 | 启动、连接、预热、checkpoint |
| 资源 | 无额外进程 | 独立服务常驻内存（数百 MB 起） |

当前 500 万条目、3 字符以上查询 0.5–7ms，靠的就是“无 IPC、无解析、无锁读”。
换成 DB 后，即使 SQL 本身很快，也多了协议、计划、行组装；**延迟大概率变差，而不是变好**。

### 16.3 并发：DB 帮的是写，不是读

- 玄览的读并发已经很好：httpd 多 worker 线程直接读 mmap；重建时旧快照继续服务，新快照
  `rename` 后原子切换，读路径没有全局查询锁。
- 数据库的强项是**行级写并发/MVCC/事务**；但玄览的写是 6 小时全量对账 + fanotify 批量 delta，
  不是 OLTP 高频单行更新。用 DB 接 fanotify 的逐事件 upsert，反而会把写入放大。
- 若目标是“更多并发查询”，先做基准测试和查询缓存/worker 调优，收益通常大于换 DB。
- 数据库也不能替代 ACL 视图/单元隔离；tenant 过滤写错一条就是越权。

### 16.4 MariaDB 与 PostgreSQL 的差异（如果一定要选）

| 维度 | MariaDB | PostgreSQL |
|---|---|---|
| 文件名子串 | `FULLTEXT` + ngram 分词；`LIKE '%x%'` 易全表扫 | `pg_trgm` GIN 支持 `LIKE '%x%'`，更贴近子串 |
| 中文 | ngram 对 CJK 友好，但分词/停用词/排名与“子串命中”不同 | pg_trgm 按字符 trigram，短查询（1–2 字）索引效果差、索引膨胀 |
| 写入/更新 | 行级写，适合高频更新 | MVCC，写入并发好，但 vacuum/膨胀需运维 |
| 运维 | 独立服务、备份、调参 | 独立服务、备份、vacuum/analyze、连接池 |
| 适用 | 已有 MariaDB 运维体系、需要全文检索 | 需要复杂 SQL/扩展、pg_trgm 子串 |

本节仅用于说明“为什么即使做分析副本也不选检索 DB”；结论仍是不引入检索 DB。
若未来做只读分析副本，PostgreSQL 的 SQL/扩展生态更合适；MariaDB 仅在已有运维体系时考虑。
这属于分析侧选型，不影响玄览运行时。

### 16.5 什么情况下才允许引入“分析副本”

分析副本不是检索后端，只允许满足以下条件时接入：

1. 需求是报表、审计、跨维度统计，而不是用户搜索；
2. 数据可接受 T+1/小时级延迟，不需要与文件索引实时一致；
3. 副本只读，禁止任何写回索引/权限的路径；
4. 有独立运维窗口，DB 故障不影响玄览检索；
5. 导出工具与快照格式解耦，DB 选型不影响主程序依赖。

即使满足，也只是“导出到 DB 做分析”，不是把检索迁到 DB。

### 16.6 建议路线

1. **保留快照为唯一检索后端**，继续优化 mmap/trigram/每用户视图；
2. 并发问题先做基准：50/100 并发下的 p50/p95、QPS、RSS、重建期间延迟；
3. 需要报表/审计时，做**离线导出**（快照 → CSV/Parquet/DB），DB 只读、不回写；
4. 不实现可插拔 `search_backend`，避免两套检索实现、两套权限语义、两套测试矩阵；
5. 若未来真的出现多节点/高频行级更新需求，再单独立项重新评估，不在本方案范围内。

### 16.8 决策记录

| 项 | 内容 |
|---|---|
| 决策 | 不引入 DB 检索后端；快照为唯一检索路径 |
| 允许 | 离线导出到 PostgreSQL/MariaDB 作为只读分析副本 |
| 禁止 | DB 参与搜索、ACL、用户视图、隔离单元、索引构建 |
| 运行时依赖 | 无新增 DB 依赖、无连接串、无迁移脚本 |
| 复审条件 | 出现多节点共享或高频行级更新需求，单独立项 |
| 生效版本 | 本文档定稿起 |

### 16.7 验证指标

| 指标 | 快照基线 | DB 对比门槛 |
|---|---|---|
| 3 字符查询 p95 | 现有 0.5–7ms | 不得高于基线 2× |
| 50 并发 QPS | 实测 | 不得低于基线 |
| 500 万条建索引 | 实测 | 不得高于基线 2× |
| 常驻内存 | 无额外进程 | 记录 DB 进程 RSS |
| ACL/单元更新延迟 | 秒级（视图） | 不得高于基线 |
| 备份/恢复 | 文件拷贝 | 记录 DB 备份/恢复时间 |

## 17. 快照方案可执行实施方案（P0–P10）

> 本节是落地清单。原则：**快照是唯一检索路径；DB 不进入运行时**。
> P0（§16 措辞与本节）已完成；P1 的解析器、`units/` 布局、CLI 与测试已落地；
> P2 的 QueryRouter 已接入 `/api/search` 与 `/api/dir`（shared / isolated / hybrid 按单元路由、
> 单元缺失 fail-closed）；P3 先完成 `@team` 扫描与单元文件生成；P4 完成单元 epoch/引用计数、
> live delta、`/api/scanmode` 与管理端三模式/分类组 UI；P5 已把单元构建改为
> **独立 Scope 遍历**（不再从共享快照过滤）；P6 完成单元级 `delta.log` 增量与
> **组 ACL 精确交集**；P7 完成压缩/GC/回滚；P8 把事件写盘改为队列 + 批量；
> P9 完成单元索引损坏检测与自动重建。

### 17.1 目标与非目标

目标：

- 管理员可选 `shared` / `isolated` / `hybrid`，默认 `shared`；
- hybrid 以**用户组**为粒度：默认共享，`isolatedGroups` 按组独立索引，未分类回退共享；
- 共享索引在 hybrid 下始终保留；
- 隔离用户 fail-closed：单元缺失/过期时不回退共享；
- 存储、配置、迁移、回滚、测试都有明确步骤。

非目标：

- 不引入 MariaDB/PostgreSQL 作为检索后端；
- 不在本期做 DB 分析副本（只预留离线导出边界）；
- 不改变文件名子串检索的语义。

### 17.2 目标架构

```text
                 scope.json（scanMode + 分类）
                          │
请求 uid ──► ScanModeResolver ──► 单元列表
                          │           │
                          │           ├─ shared  → idx/volN.idx
                          │           └─ g<gid>/u<uid> → idx/units/<unit>/volN.idx
                          ▼
              QueryRouter：合并单元结果，按路径去重
                          │
              Serve 复核：打开/下载仍走实时 ACL
```

组件：

| 组件 | 职责 | 文件 |
|---|---|---|
| Policy | 读 `scope.json`，模式/分类/defaults | `src/scanmode.c` |
| Resolver | uid + gids → 单元列表，处理覆盖/回退 | `src/scanmode.c` |
| UnitStore | `units/` 布局、`unit.json`、原子替换、清理 | `src/units.c`（P1 新建） |
| UnitBuilder | 按单元 Scope 独立遍历，生成单元索引（P5） | `scan.c` + `unitbuild.c`（P5） |
| QueryRouter | 按单元加载/合并，fail-closed | `httpd.c`（P2） |
| Admin UI | 模式、两个分类组、用户覆盖、预览 | `ui/index.html`（P3） |

### 17.4 配置项与默认值

`$TRIM_PKGVAR/scope.json` 顶层；管理端另写 `scanmode.json` 覆盖层：

| 字段 | 默认 | 说明 |
|---|---|---|
| `version` | `2` | 配置版本；v1 自动补默认 |
| `scanMode` | `shared` | `shared` / `isolated` / `hybrid` |
| `shareGroups` | `[]` | hybrid 下共享组 gid |
| `isolatedGroups` | `[]` | hybrid 下隔离组 gid |
| `shareUsers` | `[]` | 用户级显式共享 |
| `isolatedUsers` | `[]` | 用户级显式隔离 |

校验：

- 非法 mode → `shared` 并记录 warning；
- 非数字/重复 gid/uid → 忽略并记录；
- 配置不可读 → 全部默认 `shared`（fail-safe，不阻断服务）；
- 只有管理员能写；写入走 `.tmp` + `rename` + 0600。

### 17.5 解析与回退规则

```text
resolve(uid):
  shared:   [shared]
  isolated: [u<uid>]
  hybrid:
    1 uid in isolatedUsers    -> [u<uid>]
    2 uid in shareUsers       -> [shared]
    3 isolatedGroups ∩ gids   -> [g<gid>...]（全部，升序）
    4 shareGroups ∩ gids      -> [shared]
    5 otherwise               -> [shared]
```

- 用户覆盖 > 组分类；隔离组 > 共享组；未分类 = 共享；
- 多隔离组：查询加载全部单元，按路径去重；
- 隔离用户**不回退 shared**；单元缺失 → `{"error":"isolated index not ready"}` / 空结果；
- 共享用户只读 `idx/volN.idx`，不加载 `units/`；
- 组无成员/已删除：不建单元，成员按剩余规则解析。

### 17.7 迁移步骤

**V0（当前）→ P1：**

1. 备份 `settings.json`、`idx/`；
2. 写入 `scope.json`，默认 `scanMode=shared`，分类为空；
3. 启动时只创建 `idx/units/`，不改变共享索引；
4. 验证：`xuanlan scanmode --uid <admin>` 返回 `shared`；现有检索不变。

**shared → hybrid：**

1. 管理员选 hybrid，填 `isolatedGroups`，保存；
2. 后台为每个隔离组构建 `units/g<gid>/volN.idx`，共享索引继续构建；
3. 构建完成前，隔离组用户查询 fail-closed（不回退共享）；
4. 全部单元 `unit.json.aclEpoch` 与当前 epoch 一致后，路由切换生效；
5. 验证清单：隔离组用户只命中本组；共享组/未分类用户仍命中共享。

**shared/hybrid → isolated：**

1. 先确认用户数/容量（每用户一份索引）；
2. 逐个构建 `u<uid>/volN.idx`，全部成功后再切；
3. 任一步失败：保持原模式，删除未完成 `.tmp`。

### 17.8 回滚

| 场景 | 操作 | 结果 |
|---|---|---|
| hybrid/isolated 有问题 | 管理端选 shared；或 `xuanlan units rollback --index-dir DIR` | 所有用户回到共享索引；单元保留/可选清理 |
| 需要彻底清理旧单元 | `xuanlan units gc --index-dir DIR --active ... --purge` | 未激活且过期的单元删除；`.trash` 过期清理 |
| 单元索引损坏 | 加载/周期校验失败 → 入修复队列；后台重建成功前该用户 fail-closed；失败后退避 2s | 其余用户不受影响；`/api/status.repair` 可见 queued/dropped/failed |
| 单元 delta 膨胀 | 服务每 60s 对超过 `XL_DELTA_COMPACT_MB`（默认 4MB）的 delta 压缩 | 按路径保留最后事件，原子重写 |
| 单元总容量超限 | `XL_UNITS_ALERT_MB`（默认 2048MB）写日志 + `/api/status.units.alert` | 管理员清理旧单元或扩容 |
| 配置写坏 | 恢复上一版 `scope.json`（保留 `.bak`） | 解析回默认/旧分类 |
| 升级不兼容 | 保留 `idx/volN.idx`，删除 `units/` | 回到 V0 行为 |
| 构建中断 | `.tmp-*` 清理，正式单元不动 | 旧版本继续服务 |

回滚约束：

- 共享索引永远不删，是最终退路；
- 单元目录只增不覆盖，替换用 `rename`；
- 回滚不要求重建共享索引。

### 17.10 风险与观测

| 风险 | 缓解 |
|---|---|
| 分组规则误判 | Resolver 纯函数 + T1–T10；管理端预览 |
| 多组用户漏数据 | 返回全部单元并合并去重 |
| 单元构建失败 | 保留旧单元；失败单元 fail-closed |
| 单元重建后缓存未刷新 | P4 已按 `unit.json` mtime 生成 epoch，新请求加载新 mmap；旧请求用引用计数延迟释放 |
| 单元索引独立遍历 | 只读进入条件为 `x` 的子树；可穿越不可列的父目录以结构节点保留，查询期 ACL 隐藏 |
| 单元 delta 追加/压缩并发 | 单元 delta 文件全局互斥；压缩原子 rename；查询加载时可能看到旧/新完整文件 |
| 周期健康检查开销 | `XL_UNITS_CHECK_SEC` 默认 60s，最小 10s；每轮 mmap 全部单元，单元多时可调大 |
| 事件队列满 | live 回调丢弃并计数，`/api/status.events.dropped` 可见；下一次全量对账兜底 |
| writer 批量写延迟 | 队列异步，查询仍合并 live 全局 delta；单元 delta 落盘最多延迟一个批次 |
| 组单元精确交集 | 组索引只含所有成员都可读的路径；成员个人额外可见的数据不进入组索引（按规格） |
| 单元索引基线滞后 | P6 用 `delta.log` 持久化 add/delete；单元重建时清空 delta，快照与增量合并查询；超过 16MB 时拒绝追加，等下一次对账 |
| 配置漂移 | `scope.json` 版本 + `.bak` + 校验 |
| 磁盘膨胀 | 容量告警；只保留当前单元；按组粒度 |
| 回滚不彻底 | 共享索引永不删；回滚脚本只改 mode |

## 附录 B · 关键伪代码（汇总）

```text
# 1. 解析作用域
scope(uid) -> {allow[], deny[]}

# 2. 扫描
scan(root):
  ps = principals()
  state = {tm: all, rm: 0}          # 卷根特例
  walk(root, state)

walk(dir, parent):
  if !inside_registered_mount(dir): return
  if hard_denied(dir): return
  acl = load_acl(dir)
  st  = eval_masks(dir, acl, parent, ps)
  if st.tm == 0: skipped++; return                  # L1
  if st.rm != 0: emit_dir(dir, intern(st.rm))
  for e in readdir(dir):
     if e.is_dir: walk(e.path, st)
     else if st.rm != 0: emit_file(e, intern(st.rm))

# 3. 视图
view(uid) = { sid | bit(scope_masks[sid], uid) }

# 4. 查询
for hit in postings:
   if bit(rec_scope[hit]) in view(uid): emit(hit)
```
