# 版权与净室声明

本文件是《玄览》项目的合规基线。任何贡献者在提交代码前应读一遍。

## 1. 结论

- 本仓库全部源码为原创，未复制、未改编任何现有搜索引擎的实现。
- 不链接任何 GPL/LGPL 库；运行时只依赖 glibc 与 Linux 系统调用。
- 不使用 Everything、kerything 等项目的名称、图标、界面或文案。

## 2. 净室流程

写代码时遵循：**看公开接口与公开文档，不看别人的源码**。

已接触并可引用的公开资料：

- Linux `getdents64(2)`、`fanotify(7)`、`inotify(7)` 手册页；
- Linux 内核文档 `Documentation/filesystems/ext4/`（ext4 on-disk 格式的公开规范）；
- 文件系统与信息检索的通用教材概念（倒排索引、trigram、位打包、游标求交）。

明确**未使用**的内容：

- Everything 的任何二进制、反编译结果、源码或资源；
- kerything（GPL-3.0）的任何源码——本项目曾评估过它，但未复用一行；
- 任何第三方搜索界面的布局、图标、文案。

判断标准很简单：把我们的代码和上述项目放在一起，应当找不到任何一段能对上的实现、
变量命名或注释；实现路径也不同（我们用自己的记录布局、自己的块编码、自己的求交游标）。

## 3. 依赖清单

| 依赖 | 许可证 | 用法 |
|---|---|---|
| glibc | LGPL-2.1+（动态链接、系统库例外） | 常规 libc 调用 |
| Linux 内核接口 | — | 系统调用 |

服务端不引入第三方 C 库。前端仅打包 pdf.js（Apache-2.0）用于 PDF 渲染，详见 `THIRD_PARTY.md` 与 `docs/05-第三方与许可审计.md`。P1 的 ext4 裸设备读取**不**链接 `libext2fs`（LGPL-2.0）：
超级块、inode 表、目录项都是公开的磁盘格式，按规范自行解析即可，
这样既避免许可证传染，也避免运行时多一个共享库依赖。

## 5. 代码许可证

本仓库采用 **GPL-3.0**（见 `LICENSE`）。选择它的理由：

- 允许在飞牛生态内自由打包、再分发与二次开发，但衍生版本须同样开源——
  这保证了"玄览"不会出现只有作者能维护的闭源分支；
- 与第三方组件兼容：pdf.js 为 Apache-2.0、Feather 图标路径为 MIT，
  两者都可并入 GPLv3，因此分发产物可以整体以 GPL-3.0 覆盖，
  同时保留各组件原始的版权与许可声明（见 `THIRD_PARTY.md`）；
- 本项目不含任何既有 GPL 代码，许可从一开始就是自选的，
  不存在"被迫开源"的情况；
- 若使用者只是自己部署（不分发二进制），GPL 不施加任何额外义务。

## 6. 贡献者须知

- 不要粘贴来自其他项目的代码片段，包括 Stack Overflow 上的长段实现；
- 不要参考 GPL 项目的实现细节再"改写"——那是衍生作品，不是净室；
- 新增依赖前先在此文件登记许可证；
- 提交信息里写清设计动机，便于日后证明独立实现。

## 7. 与"借鉴"的边界

通用算法与数据结构不受版权保护，独立实现相同功能是合法的；
受保护的是具体表达（代码文本、注释、命名、结构组织）与商标。

因此允许：自己推导 trigram 倒排、自己做位打包格式、自己设计快照布局。
不允许：抄别人的函数体、照搬别人的结构体字段顺序与命名、复制其注释与文档措辞。
